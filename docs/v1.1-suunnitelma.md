# Urakkalaskuri – Versio 1.1 suunnitelma

> **Tila:** v1.1 toteutus valmis  
> **Perustuu:** v1 (Expo MVP) + modulaarinen laskenta  
> **Referenssilomake:** `Nimetön asiakirja (1).pdf` (ulkoverhouksen / maalaustyön kentät)  
> **Edeltäjä:** [v1-suunnitelma.md](./v1-suunnitelma.md)

---

## 1. Tavoite

Versio 1.1 tuo **modulaarisen laskennan**: käyttäjä voi rakentaa laskentalomakkeen PDF- tai työkäytäntönsä mukaisesti ilman koodimuutoksia. Lomake koostuu **sivuista** ja **kentistä**, joilla on nimet, tyypit, järjestys ja **vaikutukset** laskentaan.

**Tuoterekisteri on osa lomaketta:** valittu tuote tuo attribuutit (menekki, hinta, työkerroin…) kaavojen muuttujiin. Käyttäjän luoma muuttuja (esim. `pinta_ala`) ja tuotteen `menekki` yhdistyvät kaavassa → laskettu määrä → materiaalirivi.

Keskeinen periaate: **sama moottori kaikille lomakkeille**. v1:n kovakoodattu wizard on vain yksi valmiiksi toimitettu lomakepohja („Peruslaskenta”), ei erillinen polku.

### 1.1 Mitä muuttuu v1:stä

| v1 | v1.1 |
|----|------|
| Asetukset → Laskenta → Järjestys | **Lomakeasetukset** (sivut, kentät, nimet, vaikutukset) |
| Kiinteät wizard-vaiheet (`customer`, `duration`, `materials`) | Dynaaminen **lomakepohja** (FormDefinition) |
| Materiaalit vain tuotelistasta | Tuotteet lomakekenttinä: **suora rivi**, **attribuutit kaavoissa**, **laskettu määrä → materiaali** |
| Kate/palkkio wizardissa → siirretty asetuksiin | Pysyy asetuksissa; lomake vaikuttaa **t**, **M** ja muihin syötteisiin |
| `wizardStepOrder` JSON | `form_definition` JSON (+ migraatio) |

### 1.2 Rajaus v1.1:ään (ei v1.2)

- Lomakeeditori puhelimessa (CRUD sivuille ja kentille)
- Turvallinen kaavamoottori (rajoitettu lauseke, ei `eval`)
- Kenttätyypit: numero, teksti, valinta, tuotevalinta, laskettu, otsikko
- **Tuoterekisteri integroitu lomakkeeseen:** valittu tuote tuo attribuutit (menekki, hinta, työkerroin…) kaavojen muuttujiin
- Vaikutukset: muuttuja, materiaalirivi, keston kerroin/lisäys, materiaalikerroin
- **Yhteenveto-näkyvyys:** kentälle valittavissa, tulostetaanko muuttuja yhteenvetolomakkeelle
- **Debug-tila:** esimerkkikohde + live-laskenta kaava-asetuksissa (kalibrointi)
- v1-yhteensopivuus: oletuslomake = nykyinen wizard
- Referenssipohja PDF:n mukaiselle ulkoverhouslaskennalle (valinnainen asennuspaketti)

**Ei v1.1:ään:** PDF-vienti, pilvi, monen lomakepohjan jakaminen, visuaalinen kaavadiagrammi, monimutkainen ehtologiikka (jos/kun).

## 2. Käsitteet

```
┌─────────────────────────────────────────────────────────────┐
│  Lomakepohja (FormDefinition)                               │
│  ├── Sivu 1 (FormPage)     esim. "Pinta-alat"               │
│  │     ├── Kenttä A (number)                                │
│  │     └── Kenttä B (select) → kerroin valinnan mukaan      │
│  ├── Sivu 2 (FormPage)     esim. "Työvaiheet"               │
│  │     └── Kenttä C (select) → työnkestö- + materiaalikerroin│
│  └── Järjestelmäsivut (Asiakas, Yhteenveto) – aina mukana   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Täyttö (FormSession) – käyttäjän syötteet sivuittain       │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Laskentaputki (CalculationPipeline)                        │
│  1. Kerää syötteet → konteksti (muuttujat)                  │
│  2. Laske johdetut kentät (kaavat)                          │
│  3. Sovella kenttävaikutukset → t, M, kerroin...            │
│  4. runCalculation() → hinnat (v1-moottori)                 │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 Termit

| Termi | Kuvaus |
|-------|--------|
| **Lomakepohja** | Tallennettu määrittely: sivut, kentät, kaavat, vaikutukset |
| **Sivu** | Wizardin yksi näkymä; otsikko ja kenttälista |
| **Kenttä** | Yksittäinen syöte tai laskettu arvo (`key` = muuttujanimi) |
| **Konteksti** | Avain–arvo -kartta laskennan aikana (`seinäpinta_ala_m2` → 120) |
| **Vaikutus** | Sääntö, jolla kentän arvo muuttaa kestoa, materiaaleja tai muuttujaa |
| **Tuoteattribuutti** | Tuotelistasta valitun tuotteen arvo kaavoissa (esim. `kautettavamaali.menekki`) |
| **Oletusarvotaulukko** | Asetuksissa: ikkunan oletusmitat, ovien mitat, räystään leveys jne. |

## 3. Asetukset: Lomakeasetukset

Nykyinen **Asetukset → Laskenta** nimetään uudelleen **Lomakeasetukset**.

```
Asetukset
├── Yleinen          (ALV, kate, palkkio, tuntihinta, työryhmä – ennallaan)
├── Lomakeasetukset  ← uusi nimi, laajennettu sisältö
│   ├── Lomakepohja     sivujen ja kenttien hallinta
│   ├── Oletusarvot     PDF:n "asetukset / oletusmitat" (ikkuna, ovi, räystäs…)
│   ├── Esikatselu      testaa lomaketta ilman tallennusta
│   └── Debug           esimerkkikohde + live-laskenta (ks. luku 11)
└── Teema
```

### 3.1 Lomakepohja-editori

Toiminnot:

- **Sivut:** lisää, poista, nimeä uudelleen, järjestä (↑/↓)
- **Kentät sivulla:** lisää, poista, nimeä, järjestä, pakollisuus
- **Kenttätyypin valinta** ja tyypin mukaiset asetukset
- **Vaikutusten määrittely** kentälle (yksinkertainen lista, ei koodia)
- **Kaava** lasketuille kentille (valinnainen)
- **Yhteenvetoon** (`showOnSummary`) – näytetäänkö muuttuja yhteenvetolomakkeella
- **Palauta oletuslomake** (v1 Peruslaskenta)

Järjestelmäsivut (ei poistettavissa, voidaan piilottaa kenttiä):

| Sivu | ID | Huom. |
|------|-----|-------|
| Asiakas | `_system_customer` | Asiakastyyppi, yhteystiedot (v1) |
| Yhteenveto | `_system_summary` | Ei lomakekenttiä; tulosnäkymä |

Käyttäjän luomat sivut tulevat Asiakas-sivun ja Materiaalit/Yhteenveto-logiikan väliin (järjestys vapaasti).

## 4. Kenttätyypit

Kaikilla kentillä on:

- `id` (UUID), `key` (yksilöllinen muuttujanimi, `[a-z0-9_]+`)
- `label` (näytettävä nimi)
- `pageId`, `sortOrder`
- `required` (boolean)
- `showOnSummary` (boolean) – näytetäänkö muuttujan arvo **yhteenvetolomakkeella**
- `helpText` (valinnainen)

### 4.1 Perustyypit

| Tyyppi | UI | Arvo kontekstissa | Esimerkki PDF:stä |
|--------|-----|-------------------|-------------------|
| `number` | Desimaalikenttä + yksikkö | `number` | `kiinteä_seinäpinta_ala_m2` |
| `text` | Tekstikenttä | `string` | vapaateksti |
| `select` | Valintalista | valitun option `value` + metadata | `laudoitustyyppi` |
| `boolean` | Kyllä/Ei | `boolean` | `varinvaihto_valinta` |
| `product_quantity` | Tuote + määrä | rivi materiaaleihin | (v1 materiaalit) |
| `product_select` | Valinta tuoterekisteristä | tuotteen tiedot kontekstiin | `kautettavamaali` |
| `computed` | Vain luku (harmaa) | kaavan tulos | `laskenta_seinäpinta_ala_m2` |
| `section` | Otsikko, ei syötettä | – | "Työvaiheet:" |

### 4.2 Valinta (`select`) – option metadata

Jokaisella valinnalla voi olla **metadata**, jota kaavat ja vaikutukset käyttävät:

```typescript
interface SelectOption {
  label: string;           // "Paneeli"
  value: string;           // "paneeli"
  workFactor?: number;     // työnkestokerroin
  materialFactor?: number; // materiaalikerroin
  // geneerinen kerroin PDF:n "laudoituskerroin" -tyyppisiin
  multiplier?: number;
}
```

Esimerkki PDF: `laudoitustyyppi` → paneeli/lomalaudoitus/rimalaudoitus/hirsi, kullekin oma `multiplier`.

### 4.3 Tuotteet lomakkeessa (tuoterekisteri)

Tuoterekisteri (`Tuotteet`-näkymä) on lomakkeen **datalähde**. Sama tuote voi toimia kolmella tavalla – tai niiden yhdistelmänä.

#### 4.3.1 Tuotemallin laajennus (v1.1)

v1:ssä tuotteella on: nimi, yksikkö, yksikköhinta (alv0). v1.1 lisää valinnaiset **laskenta-attribuutit**, joita kaavat voivat käyttää:

| Attribuutti | key (kaavoissa) | Esimerkki | Yksikkö |
|-------------|-----------------|-----------|---------|
| Yksikköhinta (alv0) | `unit_price` | 12,50 | €/yks. |
| Menekki | `consumption` | 8 | m²/l |
| Ostohinta | `purchase_price` | 8,00 | €/l |
| Myyntihinta | `sale_price` | 12,00 | €/l |
| Työkerroin | `work_factor` | 1,2 | – |
| Materiaalikerroin | `material_factor` | 1,0 | – |

Tallennetaan tuotteeseen (`Product.attributes` JSON) tai erillisinä sarakkeina. Attribuutit, joita tuotteella ei ole, eivät ole käytettävissä kaavoissa (virhe tai oletus 0 editorin validoinnissa).

#### 4.3.2 Kenttätyypit tuotteille

| Tyyppi | UI | Mitä kontekstiin tulee |
|--------|-----|------------------------|
| `product_select` | Valitse tuote listasta | `{key}` = tuotteen id; `{key}.unit_price`, `{key}.consumption`, … |
| `product_quantity` | Valitse tuote + syötä määrä | Materiaalirivi heti; lisäksi `{key}.quantity`, tuoteattribuutit |

**Nimeämiskäytäntö kaavoissa:** tuotekentän `key` toimii namespace-prefixinä.

```
kautettavamaali.consumption   → valitun maalin menekki (m²/l)
kautettavamaali.unit_price    → valitun maalin yksikköhinta
pinta_ala                     → käyttäjän luoma numerokenttä (m²)
```

#### 4.3.3 Kolme tapaa käyttää tuotetta (ydinesimerkki)

Tämä on suunnitelman keskeinen idea:

```
┌──────────────────────────────────────────────────────────────────┐
│ 1. Käyttäjä luo kentän: pinta_ala (number, m²)                   │
│ 2. Käyttäjä luo kentän: kautettavamaali (product_select)         │
│    → tuotelistasta maali, jolla menekki = 8 m²/l                 │
│ 3. Käyttäjä luo lasketun kentän: materiaali_maara (computed)     │
│    Kaava: pinta_ala / kautettavamaali.consumption                │
│ 4. Kentälle materiaali_maara vaikutus: add_material              │
│    tuote: kautettavamaali (valittu tuote)                        │
│    määrä: materiaali_maara                                       │
│    → M += materiaali_maara × kautettavamaali.unit_price          │
└──────────────────────────────────────────────────────────────────┘
```

Eli: **käyttäjän muuttuja** (`pinta_ala`) ja **tuotelistasta tuleva attribuutti** (`menekki`) yhdistyvät kaavassa; tulos menee materiaaleihin valitun tuotteen hinnalla.

Toinen yksinkertaisempi tapa (v1-yhteensopiva):

```
product_quantity: valitse maali, syötä määrä 5 → suoraan M += 5 × unit_price
```

Kolmas tapa (PDF:n ikkunat):

```
number: ikkunat_lkm = 3
add_material: määrä = ikkunat_lkm, tuote = (oletustuote asetuksista)
```

**Kaikki kolme ovat v1.1:ssä tuettuja.**

#### 4.3.4 Tuotevalinta (`product_select`) – tekninen kuvaus

Kun käyttäjä valitsee tuotteen kentässä `kautettavamaali`:

1. Pipeline lataa tuotteen tuoterekisteristä
2. Kontekstiin kirjoitetaan automaattisesti:
   - `kautettavamaali` → tuotteen id (sisäinen)
   - `kautettavamaali.unit_price`, `.consumption`, `.work_factor`, …
3. Myöhemmät computed-kentät ja vaikutukset voivat viitata näihin
4. `add_material` -vaikutuksessa viitataan tuotteeseen kentän key:n kautta (ei erillistä tuote-id-kenttää)

```typescript
// Esimerkki: laskettu määrä → materiaalirivi
{
  key: 'materiaali_maara',
  type: 'computed',
  formula: 'pinta_ala / kautettavamaali.consumption',
  effects: [{
    type: 'add_material',
    productRef: 'kautettavamaali',   // sama product_select -kenttä
    quantityRef: 'materiaali_maara', // tämän kentän tulos
  }]
}
```

#### 4.3.5 Järjestelmäsivu „Materiaalit” (v1-yhteensopivuus)

Peruslomakkeessa voi säilyttää erillinen materiaalisivu (`product_quantity` -rivejä), kuten v1:ssä. Se on **sama mekanismi** kuin mikä tahansa muu sivu, jolla on `product_quantity` -kenttiä – ei erillinen kovakoodattu logiikka.

### 4.4 Yhteenvetolomake – muuttujien näkyvyys

Jokaisella kentällä (paitsi `section`) on asetus **`showOnSummary`** (Kyllä/Ei lomakeeditorissa).

| Asetus | Käyttö |
|--------|--------|
| `showOnSummary: true` | Muuttujan **label + laskettu/syötetty arvo** näkyy yhteenvetosivulla ja historiatiedoissa |
| `showOnSummary: false` | Muuttuja on vain laskennan välivaihe (esim. välikaava, tuoteattribuutti) |

**Periaate:** lomakkeessa voi olla kymmeniä muuttujia, mutta asiakkaalle näytetään vain olennaiset. Esimerkki Ulkoverhous-pohjassa:

| key | showOnSummary | Perustelu |
|-----|---------------|-----------|
| `laskenta_seinäpinta_ala_m2` | ✅ | Asiakas näkee lasketun pinta-alan |
| `laudoitustyyppi` | ✅ | Valittu tyyppi |
| `laudoituskerroin` | ❌ | Tekninen välimuuttuja |
| `kautettavamaali.consumption` | ❌ | Tuoteattribuutti, ei erillistä riviä |
| `materiaali_maara` | ✅ | Litramäärä yhteenvetoon |

**Yhteenvetosivun rakenne:**

```
1. Asiakastiedot (järjestelmä)
2. Lomakemuuttujat (showOnSummary = true, ryhmiteltynä sivuittain)
3. Materiaalirivit
4. Hintaerittely (järjestelmä: urakka, kate, ALV…)
5. Kokonaishinta
```

Järjestelmärivit (hinnat, ALV) näytetään aina. Lomakemuuttujien järjestys: `summarySortOrder` (valinnainen) tai sivun `sortOrder` + kentän `sortOrder`.

Historiatiedoissa (`history/[id]`) sama logiikka + kopiointipainikkeet vain yhteenvetoon merkityille kentille (tai kaikille – asetuksissa valinta v1.2).

## 5. Vaikutukset (Field Effects)

Kenttä voi olla **passiivinen** (vain muuttuja kaavoissa) tai **aktiivinen** (suora vaikutus laskentaan).

### 5.1 Vaikutuksen tyypit

| Tyyppi | Kuvaus | PDF-esimerkki |
|--------|--------|---------------|
| `set_variable` | Tallenna arvo kontekstiin (`key`) | kaikki syötekentät |
| `add_material` | `määrä × tuotteen unit_price` → M | suora määrä **tai** computed-määrä + product_select |
| `multiply_duration` | `t *= factor` | `työnkestokerroin` valinnoissa |
| `add_duration` | `t += hours` | lisätyö tunteina |
| `multiply_materials` | `M *= factor` | `materiaalikerroin` |
| `add_material_fixed` | `M += amount` | kiinteä materiaalilisä € |

Yhdellä kentällä voi olla **useita vaikutuksia** (esim. valinta asettaa sekä `työnkestokerroin` että `materiaalikerroin` option metadatasta).

### 5.2 Kolme tapaa käyttää syötettä ja tuotetta

**A) Suora materiaalirivi (ei kaavaa)**

```
Kenttä: ikkunat_lkm (number)
Vaikutus: add_material
  määrä: ikkunat_lkm
  tuote: (oletustuote asetuksista)
  → M += 3 × tuotteen yksikköhinta
```

tai v1-tyyli:

```
Kenttä: product_quantity (maali + määrä 5)
→ M += 5 × maalin unit_price
```

**B) Kaava käyttäjän muuttujista**

```
Kenttä: laskenta_seinäpinta_ala_m2 (computed)
Kaava: (kiinteä_seinäpinta_ala_m2 - aukkovähennykset) * laudoituskerroin
→ arvo kontekstissa, voidaan käyttää myöhemmin
```

**C) Kaava yhdistää käyttäjän muuttujan ja tuotelistaa** ← *ydinidea*

```
Kenttä: pinta_ala (number)           ← käyttäjän luoma
Kenttä: kautettavamaali (product_select)  ← tuotelistasta
Kenttä: materiaali_maara (computed)
  Kaava: pinta_ala / kautettavamaali.consumption
Vaikutus (materiaali_maara):
  add_material, tuote: kautettavamaali, määrä: materiaali_maara
→ esim. 120 m² / 8 m²/l = 15 l → M += 15 × maalin hinta
```

Mallit A–C voivat olla **samassa lomakkeessa rinnakkain**. Tuotelistasta tulevat arvot ovat kaavoissa tasavertaisia käyttäjän luomien muuttujien kanssa.

## 6. Kaavamoottori

### 6.1 Periaate

- Lausekkeet merkkijonoina, parsitaan turvallisesti (esim. oma parser tai kevyt kirjasto)
- Operandit: numerot, muuttujat, asetukset, option-kentät
- Operaattorit: `+ - * / ( )`
- Funktiot (v1.1 min): `min()`, `max()`, `round()`
- **Ei** ehtolausekkeita v1.1:ssä (`if` → v1.2)

### 6.2 Muuttujien näkyvyys

| Lähde | Esim. | Kaavasyntaksi |
|-------|-------|---------------|
| Kentän `key` (number/text) | `pinta_ala` | `pinta_ala` |
| Valinnan metadata | `laudoituskerroin` | `laudoituskerroin` (tai option export key) |
| **Tuotekentän attribuutti** | maalin menekki | `kautettavamaali.consumption` |
| **Tuotekentän hinta** | maalin myyntihinta | `kautettavamaali.unit_price` |
| Asetukset (Yleinen) | tuntihinta | `settings.default_hourly_rate` |
| Oletusarvot | ikkunan leveys | `defaults.ikkuna_leveys_m` |
| Järjestelmä (pipeline) | `t`, `M`, `U` | vain vaikutuksissa / loppulaskennassa |

**Sääntö:** `{tuotekentän_key}.{attribuutti}` – attribuutti tulee aina valitusta tuotteesta tuoterekisteristä. Jos tuotetta ei ole valittu, kaava antaa validointivirheen ennen laskentaa.

Kaavaeditorissa tuotekentät näytetään autocompletena: valitun `product_select` -kentän attribuuttilista (consumption, unit_price, …).

### 6.3 Laskentajärjestys (topologinen)

1. Käyttäjän syötteet (number, text, select, boolean)
2. **`product_select` / `product_quantity` → hae tuote, täytä `{key}.*` attribuutit**
3. Option metadata → välimuuttujat (`laudoituskerroin` valinnasta)
4. Computed-kentät riippuvuusjärjestyksessä (voi viitata sekä `pinta_ala` että `kautettavamaali.consumption`)
5. Vaikutukset: `add_material` käyttää computed-määrää + tuotekentän hintaa
6. v1 `runCalculation()`

## 7. Laskentaputki (CalculationPipeline)

```typescript
interface PipelineInput {
  formDefinition: FormDefinition;
  fieldValues: Record<string, unknown>;
  settings: AppSettings;
  defaults: FormDefaults;        // oletusmitat
  products: Product[];
}

interface PipelineResult {
  context: Record<string, number | string | boolean>;
  materialsVat0: number;
  groupDurationHours: number;
  materialLines: CalculationLine[];
  calculation: CalculationResult;  // v1-moottori
}
```

### 7.1 Vaiheet

```
┌──────────────┐    ┌─────────────────┐    ┌──────────────────┐
│ 1. Validate  │ → │ 2. Build context │ → │ 3. Compute fields  │
│   required   │    │   user inputs    │    │   (computed)     │
└──────────────┘    └─────────────────┘    └──────────────────┘
                                                    │
┌──────────────┐    ┌─────────────────┐           ▼
│ 6. Summary   │ ← │ 5. runCalculation│ ← ┌──────────────────┐
│   snapshot   │    │   (v1 engine)    │   │ 4. Apply effects │
└──────────────┘    └─────────────────┘   │  t, M, lines     │
                                           └──────────────────┘
```

### 7.2 v1-moottorin rooli

v1.1 **ei korvaa** hintakaavaa `P = (U + M) / (1 - k - p)`. Se laajentaa sitä, **mistä t ja M tulevat**:

- **t** = peruskesto (voi tulla kentästä `työryhmän_kesto_pv` × `workdayHours`) × tuotteiden/kenttien työnkestokertoimet + lisäykset
- **M** = tuoterivit + kaavojen kautta lisätyt materiaalit + kertoimet

Kate ja palkkio pysyvät **Yleinen**-asetuksissa.

## 8. Referenssilomake (PDF → lomakepohja)

Alla PDF:n (`Nimetön asiakirja (1).pdf`) jäsennys ehdotetuksi rakenteeksi. Tämä toimitetaan v1.1:ssä valmiina **pohjana** „Ulkoverhous“, jonka käyttäjä voi kopioida ja muokata.

### 8.1 Sivu: Pinta-alat

| key | label | tyyppi | kaava / vaikutus |
|-----|-------|--------|------------------|
| `kiinteä_seinäpinta_ala_m2` | Kiinteä seinäpinta-ala | number | m² |
| `laudoitustyyppi` | Laudoitustyyppi | select | option.multiplier → `laudoituskerroin` |
| `aukkovähennykset` | Aukkovähennykset | number | m² |
| `ikkunat_lkm` | Ikkunat (lkm) | number | → add_material (oletusikkuna) TAI kaava aukkoihin |
| `ovet_lkm` | Ovet (lkm) | number | → add_material (oletusovi) |
| `laskenta_seinäpinta_ala_m2` | Seinäpinta-ala (lask.) | computed | `(kiinteä_seinäpinta_ala_m2 - aukkovähennykset) * laudoituskerroin` |

### 8.2 Sivu: Räystäs ja alakatto

| key | label | tyyppi | kaava / vaikutus |
|-----|-------|--------|------------------|
| `räystäsmetrit_m` | Räystäsmetrit | number | m |

## 9. Tietomalli ja tallennus

### 9.1 Uudet tyypit (TypeScript)

```typescript
interface FormDefinition {
  id: string;
  name: string;              // "Peruslaskenta" | "Ulkoverhous"
  version: number;
  pages: FormPage[];
  fields: FormField[];
  updatedAt: Date;

interface FormPage {
  id: string;
  title: string;
  sortOrder: number;

  id: string;
  pageId: string;

  label: string;

  sortOrder: number;
  required: boolean;

  unit?: string;
  options?: SelectOption[];
  formula?: string;
  effects?: FieldEffect[];

type FieldType =
  | 'number' | 'text' | 'select' | 'boolean'

}
```

## 11. Debug-tila – kenttäkohtaiset esimerkit

Debug-tila on **lomakeasetusten kehitystyökalu**. Esimerkkiarvot **eivät ole erillisessä „esimerkkikohteessa”** vaan **jokaisen syötekentän omassa debug-kentässään**. Näin uudet tai uudelleennimetyt muuttujat eivät riko kalibrointia.

### 11.1 Periaate

```
Debug päällä
  → Kenttä A: debugExampleValue = "120"
  → Kenttä B: debugExampleValue = "18"
  → Kenttä C (select): debugExampleValue = "paneeli" → laudoituskerroin = 1,15
  → Kenttä D (computed): kaava yhdistää A, B, C automaattisesti
  → Live-paneeli näyttää välivaiheet ja lopputuloksen
```

Käyttäjä täyttää esimerkit **samassa paikassa kuin kentän muut asetukset**. Pipeline kerää kaikki `debugExampleValue`-arvot ja ajaa koko logiikan topologisessa järjestyksessä.

### 11.2 Kenttätason debug-esimerkki

```typescript
interface FormField {
  // ...
  /** Näytetään yhteenvetolomakkeella */
  showOnSummary: boolean;
  /** Debug-tilassa: esimerkkiarvo tälle kentälle (merkkijonona) */
  debugExampleValue?: string;
}
```

| Kenttätyyppi | debugExampleValue | Esim. |
|--------------|-------------------|-------|
| `number` | desimaali merkkijonona | `"120"` |
| `select` | option.value | `"paneeli"` |
| `boolean` | `"true"` / `"false"` | |
| `product_select` | productId | `"uuid-…"` |
| `computed` | – | ei syötettä; live näyttää kaavan tuloksen |

Valinnan (`select`) yhteydessä option metadata (esim. `laudoituskerroin`) exportataan kontekstiin automaattisesti valitun debug-esimerkin perusteella.

### 11.3 Debug-asetukset (globaali kytkin)

```typescript
interface FormDebugSettings {
  enabled: boolean;
  showIntermediateSteps: boolean;
}
```

Tallennetaan: `settings.form_debug`. Vain `enabled` ohjaa, näytetäänkö kenttäeditorissa debug-esimerkkikentät ja live-paneeli.

### 11.4 Live-laskenta kaava-asetuksissa

Kun debug on **päällä** ja käyttäjä muokkaa computed-kenttää:

```
┌─────────────────────────────────────────────────────────────┐
│ Kenttä: laskenta_seinäpinta_ala_m2                          │
│ Kaava:  (kiinteä_seinäpinta_ala_m2 - aukkovähennykset)      │
│         * laudoituskerroin                                  │
├─────────────────────────────────────────────────────────────┤
│ LIVE (debug-esimerkit kentittäin)                           │
│                                                             │
│ kiinteä_seinäpinta_ala_m2 = 120   ← kentän debug-esimerkki  │
│ aukkovähennykset            = 18                            │
│ laudoituskerroin            = 1,15 ← valinnan metadata      │
│                                                             │
│ Sijoitus: (120 - 18) * 1.15                                  │
│ Tulos:    117,30 m²                                         │
└─────────────────────────────────────────────────────────────┘
```

**Käyttäytyminen:**

- Pipeline ajetaan uudelleen kun kaava tai mikä tahansa kentän debug-esimerkki muuttuu
- Puuttuva debug-esimerkki → virhe: „Aukkovähennykset: debug-esimerkkiarvo puuttuu”
- `showIntermediateSteps`: listaa kaikki vaiheet järjestyksessä

### 11.5 Debug-näkymät

| Näkymä | Sijainti | Toiminto |
|--------|----------|----------|
| **Debug-kytkin** | Lomakeasetukset → Debug | Päälle/pois |
| **Debug-esimerkki** | Kentän muokkaus (syötekentät) | Esimerkkiarvo tälle kentälle |
| **FormulaDebugPanel** | Kentän muokkaus (computed) | Live sijoitus + tulos + välivaiheet |

### 11.6 Tekninen toteutus

```
src/core/form/
  pipeline.ts           runDebugPipeline(form) – lukee field.debugExampleValue
  formula/evaluator.ts  evaluateFormula, substituteFormula

src/components/form/

```

```typescript
interface DebugTrace {
  context: Record<string, number>;
  steps: DebugStep[];
  errors: string[];
}
```
