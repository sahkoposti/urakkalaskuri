# Urakkalaskuri – Versio 1.3

> **Tila:** Seuraava versio (suunnittelu)  
> **Nykyinen sovellus:** [sovellus.md](./sovellus.md) (v1.2.3)  
> **Edeltäjä:** [v1.2](./v1.2-suunnitelma.md)  
> **Arkisto:** [v1](./archive/v1-suunnitelma.md), [v1.1](./archive/v1.1-suunnitelma.md)

Versio 1.3 tuo **PDF-tulostuksen** kahdella asiakirjalla ja **uuden asetusrakenteen** tarjousta ja yritystä varten.

1. **Tarjous** – asiakkaalle annettava hintatarjous (A4, niin monta sivua kuin sisältö vie). Pohja noudattaa erillistä asetteluluonnosta.  
2. **Urakkakortti** – maalarille / työmaalle. Näyttää **tekijöiden urakan**, ei muita hintoja.

Laskelma **tallentuu jo Laske-painikkeesta**. PDF:t luodaan yhteiseltä erittelysivulta (`CalculationDetailView`).

---

## Vahvistetut päätökset

| Aihe | Päätös |
|------|--------|
| **Tallennus** | Laske kirjoittaa SQLite-rivin heti. PDF käyttää `CalculationRecord`-riviä. |
| **Tulostuspaikka** | Erittelysivu: **Luo tarjous** ja **Luo urakkakortti**. |
| **Tarjouspohja** | Kiinteä HTML-asettelu (luonnos): ylätunniste → speksikortit → hinta → lisätiedot → alatunniste. Useita PDF-sivuja tarvittaessa. |
| **Speksit** | Lomakeasetukset → **Tarjous**: mitkä lomakesivut tulostetaan. Kentät = `showOnSummary` (ei järjestelmäkenttiä). |
| **Voimassaolo** | Asetuksista, oletus **31 pv**. Näkyy „Tarjouksen tiedot” -laatikossa. |
| **Lisätiedot** | Yksi tekstikenttä Tarjous-asetuksista, tulostuu hintaerittelyn alle. |
| **Yritys** | Oma sivu **Asetukset → Yritys**: nimi, osoite, Y-tunnus, logo, myyjän nimi. Alatunnisteeseen (+ logo myös ylätunnisteeseen). |
| **Tarjous-asetukset** | **Lomakeasetukset → Tarjous** (kortin nimi vain „Tarjous”). |
| **Debug** | Ei erillistä sivua. Kytkimet **Lomakeasetukset**-sivun alaosaan (JSON-toimintojen jälkeen). |
| **Urakkakortti** | Työohje + **tekijöiden urakka** (`contractPriceVat0`). Ei muita hintoja. |

## 1. Tarjous-PDF – asettelu (luonnos)

A4 pysty. Sisältö saa jatkua **niin monelle sivulle kuin tarvitaan**. Ylätunniste ja alatunniste toistuvat jokaisella PDF-sivulla (`@page` + HTML header/footer).

```
┌─────────┬────────────────────┬─────────────────────┐
│  LOGO   │  Asiakkaan tiedot  │  Tarjouksen tiedot  │
└─────────┴────────────────────┴─────────────────────┘
─────────────────────────────────────────────────────
┌──────────────────────┐  ┌──────────────────────┐
│ Sivu 1.              │  │ Sivu 2.              │
│ (speksirivit)        │  │ (speksirivit)        │
└──────────────────────┘  └──────────────────────┘
     … lisäkortit 2 sarakkeen ruudukossa, tarvittaessa seuraavalle PDF-sivulle …

  Hinta alv0          Hinta alv
  ALV                 Ale %
                      Loppusumma

  Lisätiedot:
  (Tarjous-asetusten teksti)

─────────────────────────────────────────────────────
Footer: yrityksen nimi · osoite · Y-tunnus · logo · myyjän nimi
```

### 1.1 Ylätunniste (joka PDF-sivu)

Kolme palstaa, vaakaviiva alle.

| Palsta | Sisältö |
|--------|---------|
| **Logo** | Yritys-asetusten logo (v1.3: ColoRajaton-tiedosto, sama `BrandLogo`; oman tiedoston valinta myöhemmin jos ei ehdi) |
| **Asiakkaan tiedot** | Nimi, osoite (+ postinumero ja -toimipaikka yhdelle riville), puhelin, sähköposti |
| **Tarjouksen tiedot** | Päiväys (generoinnin päivä). Voimassaolo: „Voimassa 31 pv” (luku asetuksesta, oletus **31**). |

Asiakastyyppiä ja käänteistä ALV:ta ei piirretä tähän laatikkoon (ks. avoimet kysymykset).

### 1.2 Lomakesivujen speksit (ruudukko)

Vain sivut, jotka on merkitty päälle **Lomakeasetukset → Tarjous**.

Jokainen valittu sivu on **kortti**: otsikko = sivun nimi, alla speksirivit (`label` + arvo + yksikkö).

**Skaalaus (selkeys):**

| Tilanne | Asettelu |
|---------|----------|
| 0 speksisivua | Ruudukko pois; hintaerittely nousee ylätunnisteen alle |
| 1 sivu | Yksi kortti, täysi leveys |
| 2+ sivua | **Kaksi saraketta** (luonnos: Sivu 1 \| Sivu 2). Kolmas kortti aloittaa seuraavan rivin. |
| Paljon rivejä yhdessä kortissa | Kortti kasvaa alaspäin; `page-break-inside: avoid` kun mahtuu yhdelle PDF-sivulle, muuten rivi saa katketa |
| Paljon kortteja | Ruudukko jatkuu seuraaville PDF-sivuille; ylätunniste/footer pysyvät |

Typografia:

- Peruskoko ~11 pt, minimi ~9 pt
- Kortin sisällä ei pienennetä alle minimin – mieluummin lisää PDF-sivuja kuin ahdetaan
- Sarakkeiden leveys 50 % / 50 %, väli ~12 px
- Teeman accent kortin otsikossa tai reunassa

Järjestys = lomakkeen `sortOrder`. Tyhjä sivu (ei speksirivejä tällä laskelmalla) jätetään pois, jolloin ruudukko tiivistyy.

### 1.3 Hintaerittely

Kaksi palstaa, speksien alla. **Ei** kate-/palkkiorivejä. **Ei** erillistä työ/materiaalit-rivitaittoa tässä pohjassa (luonnos on kokonaishinta).

| Vasen | Oikea |
|-------|--------|
| Hinta alv0 → `totalPriceVat0` | Hinta alv → `totalPriceVat` |
| ALV → `vatAmount` (`vatPercent`) | Ale % → `discountPercent` (piiloon jos 0) |
| | **Loppusumma** → yksityinen: `totalPriceVat`; yritys: `totalPriceVat0` korostettuna |

Käänteinen ALV: ALV-rivin tilalla teksti „Käänteinen ALV”; „Hinta alv” voidaan jättää pois. (Varmistus: ks. avoimet kysymykset.)

### 1.4 Lisätiedot

Otsikko **Lisätiedot:** ja sen alla Tarjous-asetusten monirivinen teksti sellaisenaan (ei laskentaa). Tyhjä kenttä → osio pois.

### 1.5 Alatunniste (joka PDF-sivu)

Vaakaviiva, sitten Yritys-asetukset:

- Yrityksen nimi
- Osoite
- Y-tunnus
- Logo (pieni)
- Myyjän nimi

## 2. Urakkakortti-PDF (maalari)

Kiinteä malli, ei Tarjous-sivun sivuvalintaa. Spekseiksi **kaikki** sisältösivut (`showOnSummary`).

### 2.1 Sisältö

- Otsikko **Urakkakortti**, päivämäärä, kohde (nimi + osoite), puhelin
- **Tekijöiden urakka** = `contractPriceVat0` (alv0) – ainoa hinta
- Työn arvioitu kesto (säävaraus + ceil), työryhmän koko
- Lomaketiedot (kaikki sisältösivut)
- Materiaalit: tuote \| määrä \| yksikkö (ei hintoja)
- Asiakkaan lisätiedot + muistiinpanoalue

### 2.2 Mitä EI näytetä

Materiaalien hinnat, asiakkaan kokonaishinta, ALV, kate, palkkio, kotitalousvähennys, tarjouksen voimassaolo / lisätiedot-teksti.

## 3. Mitkä speksit tarjoukseen

Lomake laskee, **Lomakeasetukset → Tarjous** valitsee mitä asiakas näkee.

| Missä | Mitä |
|-------|------|
| **Kentät** | Mitkä kentät ovat speksejä (`showOnSummary`) |
| **Tarjous** | Mitkä **sivut** tulostetaan tarjouksen ruudukkoon |

```ts
interface OfferPageInclusion {
  pageId: string;
  enabled: boolean;
}
```

Oletus kun sivu ilmestyy listaan:

| Sivu | Tarjouksessa | Miksi |
|------|----------------|--------|
| Sisältösivu, vähintään yksi speksi | päällä | esim. Pinta-alat |
| `system: "customer"` | pois | yhteystiedot ovat ylätunnisteessa |
| `system: "materials"` | pois | ei speksikorttia |
| Vain järjestelmäkenttiä (Hinnat, kesto) | pois | hinnat ovat hintaerittelyssä |

Oletuslomake: vain **Pinta-alat** päällä.

`syncOfferPages(form, settings)`: uusi sivu → oletus; poistettu → rivi pois; otsikko aina lomakkeesta.

## 4. Lomakeasetukset → Tarjous

Näyttö: `app/settings/calculation/offer.tsx`. Pinon otsikko **Tarjous**.

```ts
interface OfferSettings {
  offerValidDays: number;       // oletus 31
  additionalInfoText: string;   // Lisätiedot-PDF
  offerPages: OfferPageInclusion[];
  offerNumberStart: number;     // jos tarjousnumero pidetään (ks. kysymykset)
}
```

Kentät UI:ssa:

1. Voimassaolo (pv), oletus 31
2. Lisätiedot (monirivinen)
3. **Lomakesivut tarjouksessa** — kytkin per sivu, „N speksiä” / „Ei tulostettavia kenttiä”
4. (Mahdollisesti) tarjousnumeron aloitus

Ei kytkimiä ylätunnisteelle, hinnalle tai footerin osille – asettelu on kiinteä luonnoksen mukaan.

## 5. Asetukset → Yritys

Näyttö: `app/settings/company.tsx`. Kortti asetusten etusivulla, Teeman jälkeen (tai ennen Teemaa).

```ts
interface CompanyProfile {
  companyName: string;
  address: string;
  businessId: string;     // Y-tunnus
  sellerName: string;     // myyjän nimi
  logoUri?: string;       // tyhjä = ColoRajaton-oletus
}
```

Logo: esikatselu siirretään Teema-sivulta tänne. v1.3 voi vielä käyttää bundlattuä `logo-colorajaton.png` jos galleriavalinta ei ehdi; kenttä `logoUri` varataan.

Tallennus: SQLite-avain `company_profile` (erillään tarjousasetuksista).

## 6. Debug Lomakeasetusten loppuun

Nykyinen `app/settings/calculation/debug.tsx` poistetaan.

**Lomakeasetukset**-sivun järjestys:

1. Sivut, Kentät, **Tarjous**
2. Lomakepohja (vie / tuo / palauta)
3. Osio **Debug** – samat kaksi kytkintä kuin nyt:
   - Debug-tila
   - Näytä välivaiheet  
   Tallennus: joko automaattinen kytkimestä (kuten muu settings) tai sama Tallenna-malli; suositus: kytkin kirjoittaa heti `saveFormDebugSettings`, toast „Tallennettu”.

Kenttäeditorin live-paneeli toimii ennallaan kun debug on päällä.

## 7. Tarjousnumero

Aiempi päätös: juokseva numero, sama laskelma pitää saman numeron.

Luonnoksessa ei ole erillistä numerokenttää. Jos numero pidetään, se sijoitetaan **Tarjouksen tiedot** -laatikkoon (päiväys + voimassaolo + nro). Myöntö ensimmäisellä tarjous-PDF:llä; urakkakortti ei näytä eikä myönnä.

Avoin: onko numero v1.3:ssa mukana.

---

## 8. Kotitalousvähennys ja materiaalitaulukko

Aiemmassa suunnitelmassa KHV-lohko ja materiaalirivit hinnoilla. **Luonnoksessa ei kumpaakaan.** v1.3-tarjouspohja noudattaa luonnosta: ei KHV-taulukkoa, ei materiaalihintarivejä. KHV-moduuli jää pois kunnes toisin päätetään. Materiaalimäärät kuuluvat urakkakorttiin.

## Avoimet kysymykset

Nämä kannattaa päättää ennen koodia. Luonnos on muuten merkitty suunnitelmaan.

1. **Tarjousnumero** – laitetaanko „Tarjouksen tiedot” -laatikkoon (päiväys + voimassaolo + nro) vai jätetäänkö v1.3:sta pois?
2. **Voimassaolon näyttö** – „Voimassa 31 pv” vai laskettu päättymispäivä (esim. 10.10.2026)?
3. **Yrityksen puhelin ja sähköposti** – footeriin mukaan vai vain luonnoksen kentät (nimi, osoite, Y-tunnus, logo, myyjä)?
4. **Hintaerittely yritysasiakkaalle** – onko „Hinta alv” + ALV-rivi pois käänteisessä ALV:ssa, ja onko **Loppusumma** aina alv0 yritykselle?
5. **Asiakkaan lisätiedot** (`customer.notes`) – tarjouksen Lisätiedot-osioon asetustekstin lisäksi, vai vain asetusten teksti?
6. **Logo Teema-sivulla** – siirto Yritykseen on suunnitelmassa; Teemaan jää vain värit ja tausta. Käykö?
