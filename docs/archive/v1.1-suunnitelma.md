## 1. Tavoite

Versio 1.1 tuo **modulaarisen laskennan**: käyttäjä voi rakentaa laskentalomakkeen PDF- tai työkäytäntönsä mukaisesti ilman koodimuutoksia. Lomake koostuu **sivuista** ja **kentistä**, joilla on nimet, tyypit, järjestys ja **vaikutukset** laskentaan.

**Tuoterekisteri on osa lomaketta:** valittu tuote tuo attribuutit (menekki, hinta, työkerroin…) kaavojen muuttujiin. Käyttäjän luoma muuttuja (esim. `pinta_ala`) ja tuotteen `menekki` yhdistyvät kaavassa → laskettu määrä → materiaalirivi.

Keskeinen periaate: **sama moottori kaikille lomakkeille**. v1:n kovakoodattu wizard on vain yksi valmiiksi toimitettu lomakepohja („Peruslaskenta”), ei erillinen polku.

### 1.1 Mitä muuttuu v1:stä

| v1 | v1.1 |
|----|------|
| Asetukset → Laskenta → Järjestys | **Lomakeasetukset** (sivut, kentät, nimet, vaikutukset) |
| Kiinteät wizard-vaiheet (`customer`, `duration`, `materials`) | Dynaaminen **lomakepohja** (`FormDefinition.pages`) |
| Materiaalit vain tuotelistasta wizard-sivulla | Materiaalit: kaavat + `add_material_fixed` / kertoimet; vanhat tuoterivit historiasta |
| Kate/palkkio wizardissa → siirretty asetuksiin | Pysyy asetuksissa; lomake vaikuttaa **t**, **M** ja muihin syötteisiin |
| `wizardStepOrder` JSON | `form_definition` JSON (+ migraatio) |

### 1.2 Rajaus v1.1:ään (ei v1.2)

- Lomakeeditori puhelimessa (CRUD sivuille ja kentille)
- Turvallinen kaavamoottori (rajoitettu lauseke, ei `eval`)
- Kenttätyypit: numero, teksti, valinta, tuotevalinta, laskettu, otsikko
- **Tuoterekisteri integroitu lomakkeeseen:** valittu tuote tuo attribuutit (menekki, hinta, työkerroin…) kaavojen muuttujiin
- Vaikutukset: materiaalilisä € (`add_material_fixed`), materiaalikerroin (`multiply_materials`), keston kerroin/lisäys (`multiply_duration`, `add_duration`)
- **Yhteenveto-näkyvyys:** kentälle valittavissa, tulostetaanko muuttuja yhteenvetolomakkeelle
- **Debug-tila:** esimerkkikohde + live-laskenta kaava-asetuksissa (kalibrointi)
- v1-yhteensopivuus: oletuslomake = nykyinen wizard
- Referenssipohja PDF:n mukaiselle ulkoverhouslaskennalle (valinnainen asennuspaketti)

**Ei v1.1:ään:** PDF-vienti, pilvi, monen lomakepohjan jakaminen, visuaalinen kaavadiagrammi, monimutkainen ehtologiikka (jos/kun).

## 2. Käsitteet

```
┌─────────────────────────────────────────────────────────────┐
│  Lomakepohja (FormDefinition)                               │
│  ├── Sivu 1 (FormPage)     esim. "Pinta-alat"               │
│  │     ├── Kenttä A (number)                                │
│  │     └── Kenttä B (select) → kerroin valinnan mukaan      │
│  ├── Sivu 2 (FormPage)     esim. "Työvaiheet"               │
│  │     └── Kenttä C (select) → kerroin kaavoissa / vaikutuksissa│
│  └── Asiakas (system: customer) – ainoa pakollinen järjestelmäsivu │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Täyttö (FormSession) – käyttäjän syötteet sivuittain       │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Laskentaputki (calculationPipeline)                        │
│  1. Kerää syötteet → konteksti (muuttujat + tuotteet)       │
│  2. Laske computed-kentät (kaavat)                          │
│  3. Kerää kenttävaikutukset (lisäykset, kertoimet)          │
│  4. Päivitä materiaalit ja kesto → järjestelmäkaavat uudelleen│
│  5. buildResultFromFormulaContext → CalculationResult       │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 Termit

| Termi | Kuvaus |
|-------|--------|
| **Lomakepohja** | Tallennettu määrittely: sivut, kentät, kaavat, vaikutukset |
| **Sivu** | Wizardin yksi näkymä; valitsee mitkä globaalit kentät näytetään (`fieldIds`) |
| **Kenttä** | Globaali syöte tai laskettu arvo (`key` = muuttujanimi) |
| **Konteksti** | Avain–arvo -kartta laskennan aikana (`kiintea_seinapinta_ala_m2` → 120) |
| **Vaikutus** | Sääntö, jolla kentän arvo muuttaa kestoa, materiaaleja tai muuttujaa |
| **Tuoteattribuutti** | Tuotelistasta valitun tuotteen arvo kaavoissa (esim. `kautettavamaali.menekki`) |
| **Oletusarvotaulukko** | Asetuksissa: ikkunan oletusmitat, ovien mitat, räystään leveys jne. |

## 3. Asetukset: Lomakeasetukset

Nykyinen **Asetukset → Laskenta** nimetään uudelleen **Lomakeasetukset**.

```
Asetukset
├── Yleinen          (ALV, kate, palkkio, tuntihinta, työryhmä – ennallaan)
├── Lomakeasetukset  ← uusi nimi, laajennettu sisältö
│   ├── Sivut         sivujen luonti, nimeäminen, järjestys (↑/↓)
│   ├── Kentät        kenttien CRUD, valintalistat, kaavat
│   ├── Oletusarvot     PDF:n "asetukset / oletusmitat" (tulossa)
│   ├── Esikatselu      testaa lomaketta ilman tallennusta (tulossa)
│   └── Debug           live-laskenta kaavojen kalibrointiin
└── Teema
```

> **v1 Järjestys poistettu:** wizard-vaiheiden järjestys korvataan `form_definition.pages` -järjestyksellä. Erillistä `wizard_step_order` -UI:ta ei enää ole.

### 3.1 Lomakepohja-editori

Toiminnot:

- **Sivut:** lisää, poista, nimeä uudelleen, järjestä (↑/↓)
- **Kentät (globaalit):** CRUD, näyttönimi, muuttuja (key), tyypit, kaavat
- **Kentät sivulla:** valitse mitkä globaalit kentät näytetään tietyllä sivulla (`fieldIds`); **yksi kenttä vain yhdellä sivulla kerrallaan**; järjestys sivulla
- **Kenttätyypin valinta** ja tyypin mukaiset asetukset
- **Vaikutusten määrittely** kentälle (`FieldEffectsEditor` kenttäeditorissa)
- **Kaava** lasketuille kentille (valinnainen)
- **Yhteenvetoon** (`showOnSummary`) – näytetäänkö muuttuja yhteenvetolomakkeella
- **Kentän kopiointi** – avaa kopion editoriin uudella keyllä (ei järjestelmäkentille). Tallentuu vasta Tallenna; Hylkää peruu luonnin.
- **Kaavaviittauksen validointi** – tallennus estetään jos kaava viittaa tuntemattomaan muuttujaan (`asetukset.*`, `settings.*` ja `materiaalit` sallittu)
- **Uusi kenttä** – tyyppi + valinnainen sivu (myös Asiakas). Ei kirjoiteta lomakepohjaan ennen editorin Tallenna-painiketta.
- **Palauta oletuslomake** (v1 Peruslaskenta) — *koko pohja: v1.2 JSON-tuonti/vienti + oletuspalautus*

**Näyttönimi vs muuttuja:** `label` on vapaatekstinen näyttönimi (esim. „Kiinteä seinäpinta-ala”). `key` on muuttujanimi kaavoissa: vain pienet kirjaimet, numerot ja alaviiva (`[a-z0-9_]+`). Editori slugifyaa keyn automaattisesti.

Järjestelmämerkinnälliset sivut:

| Sivu | Huom. |
|------|-------|
| Asiakas (`system: customer`) | Asiakastiedot – ei poistettavissa; omia kenttiä voi lisätä sivun loppuun |

Vanha `system: materials` -sivu migroidaan tavalliseksi sivuksi. Laskennan tulokset (hinnat, kesto…) ovat **järjestelmäkenttiä** (ks. §3.2).

### 3.2 Järjestelmäkentät

Laskennan tulokset (kesto tunneissa, urakkahinta, myyntihinta, kate, palkkio, ALV, kokonaishinta) ovat **järjestelmäkenttiä** (`systemKey`). Osa niistä (`kokonaishinta_alv0`, kate, palkkio, `alv_maara`) on piilotettu Kentät-UI:sta (`UI_HIDDEN_SYSTEM_FIELD_KEYS`) mutta säilyy laskennassa. Materiaalit tulevat automaattisesta kaavamuuttujasta `materiaalit` (ei FormField).

| systemKey | Näyttönimi | Kaava (lyhennetty) |
|-----------|------------|-------------------|
| `tyoryhma_kesto_h` | Työryhmän kesto (h) | `tyoryhma_kesto_pv * asetukset.tyopaivan_pituus` |
| `urakka_hinta_alv0` | Urakkahinta (alv0) | `tyoryhma_kesto_h * asetukset.tyoryhman_koko * asetukset.tuntihinta` |
| `kokonaishinta` | Kokonaishinta (alv) | `(urakka + materiaalit) / (1 - kate - palkkio)` |
| `kokonaishinta_alv0` | Myyntihinta (alv0) | `kokonaishinta / (1 + asetukset.alv_prosentti/100)` *(UI-piilotettu)* |
| `myyntikate_eur` | Myyntikate (€) | `kokonaishinta * asetukset.myyntikate_prosentti/100` *(UI-piilotettu)* |
| `myyntipalkkio_eur` | Myyntipalkkio (€) | `kokonaishinta * asetukset.myyntipalkkio_prosentti/100` *(UI-piilotettu)* |
| `alv_maara` | ALV (€) | `kokonaishinta - kokonaishinta_alv0` *(UI-piilotettu)* |

- Kaava on lukittu editorissa; näyttönimeä ja yksikköä voi muokata (näkyvillä järjestelmäkentillä)
- **Palauta oletusarvot** palauttaa kaavan ja oletusnimen
- Järjestelmäkenttiä ei voi poistaa
- Toteutus: `src/core/form/systemFields.ts`; yhdistetään lomakkeeseen `normalizeFormDefinition()`-kutsussa

### 3.3 Käyttöohje – kentät ja sivut

**Näyttönimi vs muuttuja**

| | Näyttönimi (`label`) | Muuttuja (`key`) |
|--|----------------------|------------------|
| Käyttö | Näkyy lomakkeella ja asetuksissa | Kaavoissa ja laskennassa |
| Muoto | Vapaa teksti (ä, ö, välilyönnit ok) | Vain `a-z`, `0-9`, `_` |
| Esimerkki | Kiinteä seinäpinta-ala | `kiintea_seinapinta_ala_m2` |

Editori muuntaa muuttujan automaattisesti slug-muotoon kirjoittaessasi.

**Kentät sivuille**

1. Luo kentät: **Lomakeasetukset → Kentät → Lisää kenttä**
2. Valitse sivu: **Lomakeasetukset → Sivut → [sivu] → Valitse kentät**
3. Jokainen kenttä voi olla vain **yhdellä sivulla** kerrallaan – jo sivulle valitut kentät eivät näy muiden sivujen listassa
4. Järjestä kentät sivulla nuolinäppäimillä tai järjestyspainikkeilla

**Järjestelmäkentät**

- Näkyvät Kentät-näkymän alaosassa; niitä ei voi poistaa
- Kaava on lukittu; näyttönimeä voi muokata
- **Palauta oletusarvot** palauttaa kaavan ja oletusnimen

**Debug-laskenta**

1. Ota käyttöön: **Lomakeasetukset → Debug**
2. Avaa syötekenttä → täytä **Debug-esimerkkiarvo**
3. Avaa laskettu kenttä → näet live-tuloksen ja välivaiheet (`FormulaDebugPanel`)

## 4. Kenttätyypit

Kaikilla kentillä on:

- `id` (UUID), `key` (yksilöllinen muuttujanimi, `[a-z0-9_]+`)
- `label` (näytettävä nimi)
- `required` (boolean)
- `showOnSummary` (boolean) – näytetäänkö muuttujan arvo **yhteenvetolomakkeella**
- `allowManualOverride` (computed) – lomakkeella muokattava esitäytetty arvo
- `helpText` (valinnainen)

Sivulla (`FormPage.fieldIds`): järjestys, jossa kentät kysytään/näytetään kyseisellä sivulla.

### 4.1 Perustyypit

| Tyyppi | UI-label | Arvo kontekstissa | Esimerkki |
|--------|----------|-------------------|-----------|
| `number` | Numero | `number` | `kiintea_seinapinta_ala_m2` |
| `text` | Teksti | `string` | vapaateksti |
| `select` | Valinta | valitun option `value` | `laudoitustyyppi` |
| `boolean` | Kyllä/Ei | `boolean` | `varinvaihto_valinta` |
| `product_select` | **Tuotelista** | tuotteen id + `{key}.menekki`, `{key}.yksikkohinta`… | `kautettavamaali` |
| `computed` | **Laskenta** | kaavan tulos | `laskenta_seinapinta_ala_m2` |
| `section` | Otsikko | – | "Työvaiheet:" |

**Huom.** `product_quantity` on poistettu tyypeistä; vanhat kentät migroidaan `product_select`-tyypiksi (`normalizeFormDefinition`). Erillistä „valitse tuote + määrä” -kenttää ei enää ole – materiaalit lisätään kaavalla + `add_material_fixed` tai historiasta säilyneillä tuoterivillä.

### 4.2 Valinta (`select`) – option metadata

Jokaisella valinnalla voi olla **metadata**, jota kaavat ja vaikutukset käyttävät:

```typescript
interface SelectOption {
  label: string;           // "Paneeli"
  value: string;           // "1.15" – numeerinen arvo kaavoissa
}
```

Valinnan `value` on suoraan käytettävissä kaavoissa (esim. `laudoitustyyppi` kerroin). Erillistä option-metadataa (`workFactor`, `materialFactor`) ei ole tyypissä – kertoimet mallinnetaan computed-kentillä tai vaikutuksilla.

### 4.3 Tuotteet lomakkeessa (tuoterekisteri)

Tuoterekisteri (`Tuotteet`-näkymä) on lomakkeen **datalähde**. Sama tuote voi toimia kolmella tavalla – tai niiden yhdistelmänä.

#### 4.3.1 Tuotemallin laajennus (v1.1)

v1:ssä tuotteella on: nimi, yksikkö, yksikköhinta (alv0). v1.1 lisää valinnaiset **laskenta-attribuutit**, joita kaavat voivat käyttää:

| Attribuutti | key (kaavoissa) | Tallennus (`Product.attributes`) | Yksikkö |
|-------------|-----------------|-----------------------------------|---------|
| Yksikköhinta (alv0) | `yksikkohinta` (alias `unit_price`) | `unitPriceVat0` + alias | €/yks. |
| Menekki | `menekki` (alias `consumption`) | `consumption` | esim. m²/l |
| Työkerroin | `tyokerroin` (alias `work_factor`) | `work_factor` | – |

**Ei tuettu:** `materiaalikerroin` / `material_factor` (suodatetaan pois kontekstista). Ostohinta/myyntihinta tallennetaan vain jos attribuutti on määritelty (`purchase_price`, `sale_price`).

Attribuutit, joita tuotteella ei ole, eivät ole käytettävissä kaavoissa.

#### 4.3.2 Kenttätyypit tuotteille

| Tyyppi | UI | Mitä kontekstiin tulee |
|--------|-----|------------------------|
| `product_select` | Valitse tuote listasta (Tuotelista) | `{key}` = tuotteen id; `{key}.menekki`, `{key}.yksikkohinta`, `{key}.tyokerroin` |

**Nimeämiskäytäntö kaavoissa:** tuotekentän `key` toimii namespace-prefixinä.

```
kautettavamaali.menekki       → valitun maalin menekki (m²/l)
kautettavamaali.yksikkohinta  → valitun maalin yksikköhinta
pinta_ala                     → käyttäjän luoma numerokenttä (m²)
```

#### 4.3.3 Kolme tapaa käyttää tuotetta (ydinesimerkki)

Tämä on suunnitelman keskeinen idea:

```
┌──────────────────────────────────────────────────────────────────┐
│ 1. Käyttäjä luo kentän: pinta_ala (number, m²)                   │
│ 2. Käyttäjä luo kentän: kautettavamaali (product_select)         │
│    → tuotelistasta maali, jolla menekki = 8 m²/l                 │
│ 3. Käyttäjä luo lasketun kentän: maali_hinta (computed, Laskenta)│
│    Kaava: pinta_ala / kautettavamaali.menekki                    │
│         * kautettavamaali.yksikkohinta                           │
│ 4. Kentälle maali_hinta vaikutus: add_material_fixed             │
│    määrä: maali_hinta (€)                                        │
│    → materiaalit += maali_hinta                                  │
└──────────────────────────────────────────────────────────────────┘
```

Eli: **käyttäjän muuttuja** ja **tuotelistasta tuleva attribuutti** yhdistyvät kaavassa; tulos menee materiaaleihin `add_material_fixed` -vaikutuksella.

**Huom.** Vanha `add_material` (määrä × tuotteen hinta) on legacy – ohitetaan putkessa. Käytä kaavaa + `add_material_fixed`.

#### 4.3.4 Tuotevalinta (`product_select`) – tekninen kuvaus

Kun käyttäjä valitsee tuotteen kentässä `kautettavamaali`:

1. Pipeline lataa tuotteen tuoterekisteristä
2. Kontekstiin kirjoitetaan automaattisesti:
   - `kautettavamaali` → tuotteen id (sisäinen, wizard-arvo)
   - `kautettavamaali.yksikkohinta`, `.menekki`, `.tyokerroin` (+ legacy-alias `.unit_price`, `.consumption`)
3. Myöhemmät Laskenta-kentät ja vaikutukset voivat viitata näihin

```typescript
// Esimerkki: laskettu hinta → materiaalilisä €
{
  key: 'maali_hinta',
  type: 'computed',
  unit: '€',
  formula: 'laskenta_seinapinta_ala_m2 / kautettavamaali.menekki * kautettavamaali.yksikkohinta',
  effects: [{
    type: 'add_material_fixed',
    value: 15,
  }]
}
```

#### 4.3.5 Materiaalirivit

Vanha järjestelmäsivu `system: materials` migroidaan tavalliseksi sivuksi (`migrateMaterialsSystemPages`). Oletuspohjassa **ei ole** erillistä materiaalisivua. Tuoterivit (`WizardLineDraft`) tulevat edelleen historiasta/luonnoksesta putkeen (`materiaalit`); uusiin laskentoihin materiaalit lisätään pääasiassa kaavoilla ja `add_material_fixed` -vaikutuksella. Automaattinen kaavamuuttuja `materiaalit` (ei FormField / Kentät-UI) alkaa nollasta ja päivittyy putkessa.

### 4.4 Yhteenvetolomake – muuttujien näkyvyys

Jokaisella kentällä (paitsi `section`) on asetus **`showOnSummary`** (Kyllä/Ei lomakeeditorissa).

| Asetus | Käyttö |
|--------|--------|
| `showOnSummary: true` | Muuttujan **label + laskettu/syötetty arvo** näkyy yhteenvetosivulla ja historiatiedoissa |
| `showOnSummary: false` | Muuttuja on vain laskennan välivaihe (esim. välikaava, tuoteattribuutti) |

**Periaate:** lomakkeessa voi olla kymmeniä muuttujia, mutta asiakkaalle näytetään vain olennaiset. Esimerkki Ulkoverhous-pohjassa:

| key | showOnSummary | Perustelu |
|-----|---------------|-----------|
| `laskenta_seinapinta_ala_m2` | ✅ | Asiakas näkee lasketun pinta-alan |
| `laudoitustyyppi` | ✅ | Valittu tyyppi |
| `laudoituskerroin` | ❌ | Tekninen välimuuttuja |
| `kautettavamaali.menekki` | ❌ | Tuoteattribuutti, ei erillistä riviä |
| `maali_hinta` | ✅ | Laskettu materiaalikustannus yhteenvetoon |

**Yhteenvetosivun rakenne:**

```
1. Asiakastiedot (järjestelmä)
2. Lomakemuuttujat (showOnSummary = true, ryhmiteltynä sivuittain)
3. Materiaalirivit
4. Hintaerittely (järjestelmä: urakka, kate, ALV…)
5. Kokonaishinta
```

Järjestelmärivit (hinnat, ALV) näytetään aina. Lomakemuuttujien järjestys: sivun `fieldIds`-järjestys.

Historiatiedoissa (`history/[id]`) sama logiikka + kopiointipainikkeet vain yhteenvetoon merkityille kentille (tai kaikille – asetuksissa valinta v1.2).

## 5. Vaikutukset (Field Effects)

Kenttä voi olla **passiivinen** (vain muuttuja kaavoissa) tai **aktiivinen** (suora vaikutus laskentaan laskennan **lopussa**).

**Järjestys:** ensin kaavat (`runProductionPipeline`), sitten efektit kerätään (`applyFieldEffects`), materiaalit ja kesto päivitetään, lopuksi järjestelmäkaavat uudelleen (`resolveFormContextWithEffects`).

### 5.1 Vaikutuksen tyypit (aktiiviset)

| Tyyppi | UI-label | Kuvaus |
|--------|----------|--------|
| `add_material_fixed` | Lisää materiaaleihin | `materiaalit += value` (€, alv 0) |
| `multiply_materials` | Kerro materiaaleja | `materiaalit *= value` (kerroin, esim. 1,1 = +10 %) |
| `multiply_duration` | Kerro kestoa | `kesto_h *= value` (kerroin) |
| `add_duration` | Lisää kestoon | `kesto_h += value` (tunnit) |

| Tyyppi | Tila |
|--------|------|
| `add_material` | **Legacy** – ohitetaan putkessa ja filtteröidään editorista |
| `set_variable` | Tyypissä, ei toteutettu erillisenä efektinä (syötekentät kirjoittavat kontekstiin suoraan) |

Yhdellä kentällä voi olla **useita vaikutuksia** (esim. valinta kertoo keston ja materiaalit erillisillä computed-kentillä).

### 5.2 Esimerkkejä

**A) Kiinteä materiaalilisä**

```
Kenttä: lisamaalaus (boolean)
Vaikutus: add_material_fixed, arvo: 15
→ +15 € materiaalikustannuksiin
```

**B) Kertoimet**

```
Kenttä: vaikea_työ (boolean)
Vaikutus: multiply_duration, arvo: 1,1
→ kesto × 1,1 (+10 %)

Kenttä: kallis_materiaali (boolean)
Vaikutus: multiply_materials, arvo: 1,15
→ materiaalit × 1,15
```

**C) Keston lisäys**

```
Kenttä: lisatyö (boolean)
Vaikutus: add_duration, arvo: 4
→ +4 h kestoon
```

## 6. Kaavamoottori

### 6.1 Periaate

- Lausekkeet merkkijonoina, parsitaan turvallisesti (esim. oma parser tai kevyt kirjasto)
- Operandit: numerot, muuttujat, asetukset, option-kentät
- Operaattorit: `+ - * / ( )`
- Funktiot (v1.1 min): `min()`, `max()`, `round()`
- **Ei** ehtolausekkeita v1.1:ssä (`if` → v1.2)

### 6.2 Muuttujien näkyvyys

| Lähde | Esim. | Kaavasyntaksi |
|-------|-------|---------------|
| Kentän `key` (number/text) | `pinta_ala` | `pinta_ala` |
| Valinnan `value` | laudoitustyyppi | `laudoitustyyppi` |
| **Tuotekentän attribuutti** | maalin menekki | `kautettavamaali.menekki` |
| **Tuotekentän hinta** | maalin hinta | `kautettavamaali.yksikkohinta` |
| Asetukset (Yleinen) | tuntihinta | `asetukset.tuntihinta` (alias `settings.default_hourly_rate`) |
| Materiaalit (putki) | tuoterivit + efektit | `materiaalit` |
| Järjestelmä (pipeline) | kesto, hinnat | järjestelmäkenttien kaavoissa |

**Sääntö:** `{tuotekentän_key}.{attribuutti}` – kanoniset nimet suomeksi (`menekki`, `yksikkohinta`, `tyokerroin`). Jos tuotetta ei ole valittu, kaava antaa validointivirheen ennen laskentaa.

Kenttäeditorissa tuotekentät näytetään `ProductFormulaHints`-komponentilla (ei vielä täyttä autocompletea kaavaeditorissa).

### 6.3 Laskentajärjestys

1. Käyttäjän syötteet (number, text, select, boolean, product_select)
2. **`product_select` → hae tuote, täytä `{key}.menekki`, `{key}.yksikkohinta`…**
3. Computed-kentät (Laskenta) riippuvuusjärjestyksessä
4. **Kenttävaikutukset kerätään** (`add_material_fixed`, `multiply_materials`, `add_duration`, `multiply_duration`)
5. Materiaalit ja kesto päivitetään efektien jälkeen
6. Järjestelmäkaavat uudelleen lopullisilla arvoilla
7. `buildResultFromFormulaContext` → `CalculationResult`

Debug-putki (`runDebugPipeline` / `pipeline.ts`) noudattaa samaa kaavajärjestystä; efektit tuotannossa `calculationPipeline.ts`:ssä.

### 7.2 Järjestelmäkaavojen rooli

v1.1 **ei korvaa** hintalogiikkaa: urakka, kate, palkkio ja ALV tulevat **järjestelmäkenttien kaavoista** (`systemFields.ts`). Putki laajentaa sitä, **mistä kesto ja materiaalit tulevat**:

- **kesto** = `tyoryhma_kesto_pv` × `asetukset.tyopaivan_pituus` (+ `multiply_duration`, `add_duration`)

## 11. Debug-tila – kenttäkohtaiset esimerkit

Debug-tila on **lomakeasetusten kehitystyökalu**. Esimerkkiarvot **eivät ole erillisessä „esimerkkikohteessa”** vaan **jokaisen syötekentän omassa debug-kentässään**. Näin uudet tai uudelleennimetyt muuttujat eivät riko kalibrointia.

### 11.1 Periaate

```
Debug päällä
  → Kenttä A: debugExampleValue = "120"
  → Kenttä B: debugExampleValue = "18"
  → Kenttä C (select): debugExampleValue = "paneeli" → laudoituskerroin = 1,15
  → Kenttä D (computed): kaava yhdistää A, B, C automaattisesti
  → Live-paneeli näyttää välivaiheet ja lopputuloksen
```

Käyttäjä täyttää esimerkit **samassa paikassa kuin kentän muut asetukset**. Pipeline kerää kaikki `debugExampleValue`-arvot ja ajaa koko logiikan topologisessa järjestyksessä.

### 11.2 Kenttätason debug-esimerkki

```typescript
interface FormField {
  // ...
  /** Näytetään yhteenvetolomakkeella */
  showOnSummary: boolean;
  /** Debug-tilassa: esimerkkiarvo tälle kentälle (merkkijonona) */
  debugExampleValue?: string;
}
```

| Kenttätyyppi | debugExampleValue | Esim. |
|--------------|-------------------|-------|
| `number` | desimaali merkkijonona | `"120"` |
| `select` | option.value | `"paneeli"` |
| `boolean` | `"true"` / `"false"` | |
| `product_select` | productId | `"uuid-…"` |
| `computed` | – | ei syötettä; live näyttää kaavan tuloksen |

Valinnan (`select`) yhteydessä option metadata (esim. `laudoituskerroin`) exportataan kontekstiin automaattisesti valitun debug-esimerkin perusteella.

### 11.3 Debug-asetukset (globaali kytkin)

```typescript
interface FormDebugSettings {
  enabled: boolean;
  showIntermediateSteps: boolean;
}
```

Tallennetaan: `settings.form_debug`. Vain `enabled` ohjaa, näytetäänkö kenttäeditorissa debug-esimerkkikentät ja live-paneeli.

### 11.4 Live-laskenta kaava-asetuksissa

Kun debug on **päällä** ja käyttäjä muokkaa computed-kenttää:

```
┌─────────────────────────────────────────────────────────────┐
│ Kenttä: laskenta_seinapinta_ala_m2                          │
│ Kaava:  (kiintea_seinapinta_ala_m2 - aukkovahennykset)      │
│         * laudoituskerroin                                  │
├─────────────────────────────────────────────────────────────┤
│ LIVE (debug-esimerkit kentittäin)                           │
│                                                             │
│ kiintea_seinapinta_ala_m2 = 120   ← kentän debug-esimerkki  │
│ aukkovahennykset            = 18                            │
│ laudoituskerroin            = 1,15 ← valinnan metadata      │
│                                                             │
│ Sijoitus: (120 - 18) * 1.15                                  │
│ Tulos:    117,30 m²                                         │
└─────────────────────────────────────────────────────────────┘
```

Kun käyttäjä muokkaa tiettyä computed-kenttää, pipeline suodattaa välivaiheet **vain kyseiseen kaavaan liittyviin kenttiin** (`focusFieldKey`).

**Käyttäytyminen:**

- Pipeline ajetaan uudelleen kun kaava tai mikä tahansa kentän debug-esimerkki muuttuu
- Puuttuva debug-esimerkki → virhe: „Aukkovähennykset: debug-esimerkkiarvo puuttuu”
- `showIntermediateSteps`: listaa kaikki vaiheet järjestyksessä

### 11.5 Debug-näkymät

| Näkymä | Sijainti | Toiminto |
|--------|----------|----------|
| **Debug-kytkin** | Lomakeasetukset → Debug | Päälle/pois |
